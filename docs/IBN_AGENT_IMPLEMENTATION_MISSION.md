# Agent Implementation Mission — Adaptive Smart Factory × IBN

**MANDATORY READING:** IBN_SMART_FACTORY_EVALUATION.md; AGENT_ADAPTER_MATRIX.md; ENGINEERING_INTENT_AND_REPORTING.md; actual Smart Factory repository implementation; and current installed IBN source, owner manifests, runtime tests and approved engineering standards.

## Mission objective

Evaluate, design, implement and independently verify a production-quality, **per-engineer local Windows** integration. Most engineers use Codex; all other **actually installed and supported** IBN agents should receive their own compatible instruction profile and native adapter. Do not deploy one giant Codex Core to every agent. No centralized orchestrator or extra paid API requirement.

Work through the real engineering requirements, not invented technical values. Codex must manage its own mission and workers; IBN remains the authoritative domain Brain/OneBrain, Graphify, AI Memory, Skills and engineering QA. Non-Codex clients may use a portable mission/event bridge ONLY where native capabilities permit it.

## Action 0 — preserve and inventory

1. Discover the actual current IBN installation and version per PC; historical Drive packages are baselines, NOT evidence of present installation.
2. Read the complete Smart Factory source, CI, installer, instruction precedence, watcher, mission, routing and token-report logic.
3. Enumerate installed IBN/agent/user-owned Skills by owner, content/support hashes, version, native execution support and approval status. Preserve 7,517 historical canonical Skills as a historical scale reference, not a promised current count.
4. Read IBN native OneBrain, Graphify, standards, FastPath, Skill Fusion, Skill Recorder and AI Memory interfaces; identify office/client/project scopes and engineering references.
5. Discover agent versions, their documented instruction/hook/config capabilities, actual owned files and permissions. Protect agent user data and company project content.
6. Create isolated, uniquely named stage; collect baseline hashes, failure evidence and rollback procedure.

Do not copy, overwrite, or migrate the full IBN 1.86 GB source archive into the Smart Factory repository. Do not place internal Drive IDs, private client files, passwords, tokens or agent session transcripts in public GitHub.

## Action 1 — Smart Factory hardening (release blocking)

- SF-01: global AGENTS.override collision: own a versioned managed block; check actual instruction hierarchy in a fresh Codex session, preserve all IBN/user instructions, eliminate duplication and test update/uninstall.
- SF-02: unsafe Smart-Exec writes: eliminate unconditional noninteractive approval for write work, enforce read-only default and real path/sandbox permission checks, protect live engineering projects, support explicit scoped authorization. Test negative cases including symlink/junction escapes.
- SF-03: routing: integrate bilingual Arabic/English engineering discipline, risk, standard/geometry consequence, verification burden and IBN Skill metadata; preserve explicit model choice and avoid extra paid APIs.
- SF-04: installer: verify the **exact** downloaded artifact with a trusted pinned checksum/signature, stage safely and roll back failures. Source tag ZIP and release artifact ZIP differ and are not hash interchangeable.
- Supplementary: align stale watcher heartbeat rules, idempotent mission state, concurrent worker scope handling, honest live telemetry, quota checkpoint wording and release evidence.

## Action 2 — Intent + source-grounding (before execution)

Implement the Engineer Request Contract with explicit requested deliverables, drawings/floors/systems, exclusions, units, revisions, jurisdiction/edition, inputs, expected verification and missing essential values. Preserve Arabic/English nuances and user-negations. Every material engineering claim must have an official/cited reference or observed model evidence; otherwise UNKNOWN/SOURCE_NOT_FOUND. No spontaneous design value invention. Generate the compact engineer request receipt before planning or editing.

## Action 3 — Minimal per-agent injection

For each installed client (Codex, Claude Code, Cursor, OpenCode, Gemini CLI, Antigravity, Copilot or proven other), build capabilities through real version-specific discovery. Select only compatible native instruction blocks, hooks, Skills and tool CLI. Preserve existing blocks, prefer user-scoped/adaptor-owned files, prove that IBN-First stays effective in a new session. Unsupported agents must report UNSUPPORTED/NOT_TESTED rather than installing imaginary hooks. Codex gets native Smart Factory routing; other clients receive only supported IBN and mission-event features, not a fake Codex worker.

## Action 4 — Native IBN intelligence

- Read path: bounded, scoped Brain/OneBrain/Graphify/official standards and Skill search through native interfaces, with source edition/page/model refs and owned content hashes.
- Mission path: stable Smart Factory task ID versus IBN execution and QA IDs, explicit owners and idempotent event journal. Keep final engineering verification separate from worker completion.
- Memory path: verified/approved results only, via native AI Memory API, preserving scope/provenance and no duplicate memories.
- Graph path: native Graphify queries and approved writebacks, stable node/edge IDs, no synthetic authoritative facts, no destructive rebuild.
- Skill path: IBN Skill Recorder approval remains mandatory; a Skill may be guidance only, not an executable.
- Native execution: protect AutoCAD/Revit sessions and file state; use IBN's existing source-backed, read-only and guarded transaction policies.

## Action 5 — Efficient self-organizing execution

Build an acceptance-driven task DAG, not a speculative task explosion. Classify discoveries and dependencies explicitly. Reuse FastPath for selective retrieval; use content hashes and delta inspection. Assign token/context budget by phase; reserve verification/report space, and classify observed usage versus unknown. Limit redundant retries and repeated searches; diagnose actual cause. Optimize verified outputs and error reduction; do not trade accuracy for low token usage. Only agent-specific model dispatch where authorized.

## Action 6 — Truthful end-of-task engineer report

Every supported agent must produce a standard, durable report containing: user request and exclusions; work performed; output files/diffs; verified engineering source references and native evidence; real checks run; work NOT tested; assumptions, blockers and unknowns; actual model and tokens if observed; post-task Memory/Graphify receipts; task states; checkpoint and next action. Distinguish IMPLEMENTED, TECHNICALLY_CHECKED, ENGINEERING_VERIFIED, ENGINEER_APPROVED. Never call a self-reported agent result an approved engineering design.

## Action 7 — Verified local tests and package

Run Smart Factory native Windows tests; isolated regression tests for all SF-01..SF-04; IBN native tests; each actually installed agent's fresh-session instruction and tool smoke test; bilingual engineering intent/parity and negation tests; source citation refusal; 7,500+-Skill indexing/dedupe fidelity; scoped graph/memory replay; native engineering QA gate; partial writes; stale observer; no paid billing; clean installation, update, repair, rollback and uninstall. Use non-production data and isolated CAD/BIM fixtures only unless explicitly approved. Do not modify live drawings for smoke tests.

Required test statuses: PASS, FAIL, BLOCKED, NOT_TESTED, NOT_AVAILABLE. Require exact commands, evidence, version, current machine and measured counts. Historical CI or Drive report alone does not count as present E2E verification.

## Final go/no-go

Do not claim production READY until SF-01..SF-04, G01..G30, A01..A10 and E01..E12 each have an observed status and **all critical mandatory gates PASS**. Degraded but safe optional agents may be marked NOT_AVAILABLE; no false claim of universal hook support. If blocked, preserve completed work and exact deterministic recovery instructions, not vague promises.

**Execute on the authorized local machine; do not stop at a plan, do not introduce a paid API, do not push production software directly to main, and do not destroy existing IBN or project files.**
